# 教育分享类 PPT 制作（暖调纸感 · SVG 工程流）

这套流程解决的不是"生成几页幻灯片"，而是**一个人反复改、PPT 还要能自己继续编辑**的真实场景。核心结论先摆在这里：

1. **每页写成 SVG，再整体编译成 pptx**——不是直接调 python-pptx 摆文本框。SVG 好写、好预览、好改，编译后每个元素都是原生形状，用户能在 PowerPoint 里接着改。
2. **用户一旦手工改过，后续只能做"单页替换"**——以用户最新文件为底，只换目标页的 slide XML + rels + 媒体，并证明"其余条目字节级一致"。绝不能整包覆盖。
3. **讲稿与 PPT 同源同序**——逐字稿按页排段，改页必改稿。

## 零、开始前先问清楚（缺一项就去问，不要猜）

| 项 | 为什么要 | 示例 |
|---|---|---|
| 场景 | 决定页数与信息密度 | 三区教研分享 / 家长会 / 赛课说课 |
| 受众 | 决定术语与解释深度 | 特教同行、教研员 |
| 时长 | 决定页数（约 1 页/1 分钟）与讲稿字数 | 30 分钟 → 28–32 页 |
| 分享人 / 单位 | 封面与落款 | 从化区西宁小学　何恺涓 |
| 是否已有素材 | 决定配图走"解包课件"还是"视频截帧" | 希沃 .enbx、课堂实录 mp4 |
| 是否要逐字稿 | 决定要不要同步维护 docx | 要 / 不要 |

拿到后立刻写 `spec_lock.md`（见 `references/build-pipeline.md`），**漏掉 `## canvas` 段编译器会拒绝导出**。

## 一、视觉系统（一套，不要中途换）

暖调纸感教育风。完整色卡、字号阶梯、栅格与装饰件见 `references/visual-system.md`，此处只记最常用的：

- 底色 `#FAF6EE`（暖米）｜主文字 `#1E3A38`｜次要文字 `#5C716E`｜主色 `#2F8B84`（墨绿）｜暖黄 `#F2C879`｜金句线 `#E8A84E`｜边框 `#E6D8BF`｜波浪 `#E4F0EC`｜图注 `#8A7A60`
- 字号只用四级：页标题 **44**、模块标题/正文 **26–32**、注释 **22**、封面主标题 **64**
- 内容左右边界 **88px**；卡片间距 **64–76**；卡片内边距 **30**
- 每页固定四件套：双层纸边框 + 左上/右上角刻线 + 左边缘黄色书签条 + 底部浅绿波浪 + 右下页码胶囊

**铁律：同一组页面共用同一套骨架。** 不要在某一页自创卡片、换圆点颜色、加点线装饰——用户会立刻发现"怎么和旁边那页不一样"。要差别只在"有图/无图"和"文字块位置"上。

## 二、页面生产

版式库（26 种已验证版式，含可直接改的 SVG 片段）见 `references/layouts.md`。生产顺序：

1. 先定**页面清单**（序号｜页面标题｜版式类型），让用户过一遍再动手。
2. 每页一个文件：`svg_output/NN_slug.svg`，编号两位数、从 01 连续。
3. 每页渲染 PNG 自检（`scripts/render_svg.py`），重点看：文字有没有溢出卡片右边界、底部波浪有没有压字、图有没有被裁变形。
4. 全部页齐了再编译，不要一页一页编译。

## 三、编译与交付

```bash
# 1) 质量检查（必须先跑，否则 release 导出会被拒）
python3 <skill>/scripts/run_svg.py <ppt-master>/scripts/svg_quality_checker.py <项目目录> \
        --canonical-authoring --stage final --json
# 2) 编译
python3 <skill>/scripts/run_svg.py <ppt-master>/scripts/svg_to_pptx.py <项目目录>
```

细节（sandbox mkdir 报错的绕法、spec_lock 必填项、导出目录命名）见 `references/build-pipeline.md`。

## 四、用户改过之后：单页替换（本流程最关键的一步）

用户几乎一定会在 PowerPoint 里自己改几页。之后所有改版都必须走这条路：

```bash
python3 <skill>/scripts/page_replace.py \
    --src  "交付版.pptx" \
    --page 29 \
    --slide-xml <新编译导出>/ppt/slides/slideNN.xml \
    --out /tmp/out.pptx
```

脚本自动完成：备份 → 主题色落地（schemeClr→srgbClr）→ 删 `srcRect` → 换 slide XML 与 rels → 补媒体 → **逐条比对证明其余条目字节级一致** → 悬空 Target 检查 → 原子写回。

为什么必须这样，以及校验数字怎么读，见 `references/page-replace.md`。

## 五、素材

两条来源，都在 `references/media.md` 里写了完整命令：

- **现有课件解包**（希沃 .enbx = zip）：取图后登记 `image_sources.json`（文件名 / 来源页 / 用途），避免后期找不到出处。
- **视频截帧**：先按 `fps=1/N` + `tile` 拼网格扫全片定位，再用单帧 `-ss` 精确取，`crop` 掉字幕，`scale` 到 502×282 之类的目标尺寸。

图片进 SVG 三条硬规定：路径写 `../images/xxx.jpg`；`preserveAspectRatio="xMidYMid slice"`；编译后检查并删掉自动生成的 `<a:srcRect>`。

## 六、逐字稿

格式、语气、时长校准、蓝字论文补充的做法见 `references/script.md`。三条最容易踩的：

- **语气是教研分享，不是聊天**：不用第二人称"你"，不用"泼盆冷水""说人话"这类粗犷口语，互动感只保留一两处。
- **总览页不要逐条念 PPT**：只交代骨架，陌生名词出现时紧跟一句"这个后面单独讲"。
- **字数按 200 字/分钟校准**，超了就压重复，不要压内容。

## 七、收尾

1. 备份进 `<项目>/validation/`，命名 `交付备份_<动作>前.pptx`，能一眼看出是"做这事之前"。
2. 项目档案追加变更记录：**改了什么 / 根因 / 校验数字 / 备份路径**。根因最重要——例如"背景发白"的真因是主题色未落地，不写下来下次还会踩。
3. `present_files` 交付，正文里说清"改了哪页、动了什么、校验结果"。

## 八、六个必看的坑

`references/pitfalls.md` 有完整描述。先记标题：

1. 新编译页用 `schemeClr` 引用主题 → 网页预览显示白底（必须落地为 `srgbClr`）
2. `srcRect` 多数是合法裁剪（千分比），别乱删——只有值明显失常才是 bug
3. 删页必须改 `sldIdLst` + rels + `[Content_Types].xml`，且正则要用 `[^>]*`
4. 含视频的页被清空时，媒体文件会连带删除 → 恢复必须连媒体一起补
5. 不要替用户编数据（曾自造"备课省 40 分钟"，用户从未说过）
6. 改版不要自创视觉元素（曾把圆点列表改成圆角卡片，被要求整页返工）
