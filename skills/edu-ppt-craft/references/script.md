# 逐字稿：与 PPT 同源同序的讲稿

## 一、结构

- **一段一页**：段落顺序严格对应 PPT 页序，改页必改段，改段必查页。
- **小标题带时长**：`〔开场·约2分钟〕` `〔第二部分·约7分钟〕`，方便现场控时。
- **段落只写"要念出口的话"**，不写备注、不写舞台指示（`〔停顿〕` 例外，它是要念到节奏里的）。
- 标注体系：
  - `〔停顿〕` —— 讲者需要停一拍的地方，通常在一段论证结束、要翻页之前
  - `〔论文补充·章节〕` —— 见第四节

## 二、语气（最常被退回的地方）

用户是**一线教师做教研分享**，不是演讲比赛，也不是产品发布会。基调是"把自己的做法讲清楚"，语气平稳、少起伏。

**要**：

- 第一人称叙述："我后来特意拿另一门课又试了一遍"
- 完整陈述句，句子长度介于口语与论文之间
- 逻辑连接显式化："所以""也就是说""这里要说明的是"

**不要**：

| 别写 | 改成 |
|---|---|
| 你／你们（"你把他带进去了"） | 第三人称或省略主语（"需要老师一步一步带"） |
| 反问句堆叠（"几张图能撑起什么呢？"） | 陈述（"几张图撑不起一个完整的情境"） |
| 粗犷口语（"泼盆冷水""说人话，不吹""真东西"） | "AI 会犯错""全是真实的活活动""实际情况" |
| 强互动（"大家可以注意""我常跟年轻老师说"） | "请各位注意"，或直接陈述 |
| 自我评价（"这一课我最满意的地方"） | 保留少量，一整套讲稿不超过 3 处 |

互动感只保留一两处即可（如"台下可能有老师会想"），多了就显得油。

## 三、时长校准

**按 200 字/分钟**（教研分享的正常语速，比演讲慢）：

```
分钟数 = 正文字数 ÷ 200
```

- 30 分钟的分享，正文控制在 **5,800–6,400 字**
- 超时就**压重复**，不要压内容：同一件事讲两遍的地方合并、空转的总结句删掉
- 逐段统计字数的做法：

```python
import re, zipfile
x = zipfile.ZipFile(docx).read("word/document.xml").decode()
paras = re.findall(r'<w:p\b.*?</w:p>', x, re.S)
for i, p in enumerate(paras):
    t = ''.join(re.findall(r'<w:t(?:\s[^>]*)?>(.*?)</w:t>', p, re.S)).strip()
    if t: print(i, len(t), t[:40])
```

## 四、蓝字"论文补充"

当用户已有一篇论文、希望讲稿能对照取用时：把**论文里有、讲稿没展开**的内容，写成可直接念的口语句子，插在对应位置，用蓝色 + 段首标记。

- 颜色 `#1F6FB2`，段首 `〔论文补充·章节名〕`
- 文首"本稿说明"加一句交代蓝色段落的用途
- 蓝字段落**不参与时长计算**，是备选素材；全念会超时，现场挑 2–3 处
- 论文口径与讲稿口径不一致时（例如论文写"四类技术"、实际是"三类"），**在档案里留一条提醒**，不要悄悄改论文，也不要按论文的错口径讲

## 五、删口水词的四条规则

**只压冗余，不改口吻。**

1. **空转的总结句**：说完又总结一遍的（"这也是最可贵的地方——课一开始……"）直接删，接破折号或逗号
2. **自我重复**：同一件事在两个段落各讲一次 → 留信息量大的那处，另一处换说法或删掉具体账
3. **填充词**：说实话／其实／我想／我打算／大家可能／可以说／就是说 —— 删掉不影响语义的一律删
4. **绕的句子**："方法本身是好的，可我做得不够好" → "方法没错，是我做得不够"

不要动：用户的个人表述、加粗小标题、蓝字段落。

## 六、总览页的念法（重要）

PPT 上的总览页（如"六步流程""五样东西"）**不要逐条念**。逐条念会把后面页面才解释的细节提前抖出来，听众当场就卡住。

正确写法：**只交代骨架 + 给陌生名词挂一个"后面单独讲"**。

> 这一页是整套素材的制作路线，六步。我先把顺序交代清楚，具体做法后面一步一步说。
>
> 前三步是连着的：先定角色和画风，再批量出图，然后把连贯的图转成视频、配上旁白。
>
> 第四步是数字人，让画面里的角色开口说话。**这一步我后面单独讲**，它解决的问题和前面不一样。
>
> 第五、六步是收尾：做成提示卡，最后逐张人工审核。
>
> 六步走完，下面按这个顺序，一类一类说。

三条原则：

- 细节留到展开页讲，总览页不抢戏
- 陌生名词出现时立刻报"后面单独讲"，听众就不会卡住
- 末句要能接住下一页的第一句

## 七、改 docx 的技术要点

用 `python-docx` 整段重写会**丢格式**。正确做法是解包改 XML：

```bash
cd /tmp && rm -rf dz && mkdir dz && cd dz
unzip -o -q "讲稿.docx"
# 改 word/document.xml，再按原顺序重新打包
```

四条经验：

1. **沿用原段的 `pPr` / `rPr`**：从相邻段取 `<w:pPr>` 和 `<w:rPr>` 原样拷贝，不要自己构造
2. **加粗状态照原稿判断**：原段首 run 加粗就跟着加粗，不要"顺手统一"。严格判断要排除 `<w:b w:val="0"/>`
3. **引号统一**：全稿检查直引号 `"` 与中文引号 `“”` 是否混用。Word 手动输入的是直引号，脚本里写的是中文引号，混进来很显眼
4. **打包只换 `word/document.xml`**，其余条目逐字节复制，打包后用 `textutil -convert txt -stdout` 验证可读

检查残留格式：

```python
# 找出整段带下划线的段（用户手改常留下）
[p for p in paras if 'w:u w:val="single"' in p]
```

## 八、内容一致性检查

讲稿与 PPT 之间最容易出现的不一致，交付前逐项过：

- [ ] 角色名前后统一（曾出现前文"小兔"、后文"小猪"）
- [ ] 数字只出现一次口径（页数、人数、步数、时长）
- [ ] **没有任何用户没提供过的数字**（曾自造"备课省 40 分钟"，用户从未说过）
- [ ] 术语统一（"三类技术"不要忽然变"四类"）
- [ ] 讲稿提到的小标题与 PPT 上的标题一致
